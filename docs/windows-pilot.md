# Испытание Windows / LAN, версия 0.2.0-pilot

Это промежуточная реализация этапа 0.2, **не готовая система клуба**.
Сначала один игровой ПК, учебный баланс и сохранённые игровые файлы.
Состояние проверок и ограничения: [validation.md](validation.md).

## Состав комплекта

- `Admin/Club.Admin.exe` — отдельное нативное приложение сотрудника (WinForms).
  Создание владельца, места/тарифа, пополнение, бесплатное время, пауза/возобновление/
  завершение, возврат, привязка устройства, отчёт и журнал.
- `Server/Club.Server.exe` — ASP.NET Core / SQLite на ПК администратора.
  При запуске Admin автоматически запускает соседний Server, если порт 5080 свободен.
  Закрытие Admin не останавливает сервер. Остановка сервера — Ctrl+C в его окне.
- `Visitor/Club.Visitor.exe` — отдельное нативное приложение посетителя: регистрация,
  вход, баланс, пакеты, покупка для своего ПК, таймер, каталог игр и предупреждение за 5 минут.
- `Agent/Club.Agent.exe` — Windows-служба `ClubAgent` от LocalSystem, установленная
  на игровой ПК. Хранит ключ устройства и остаток; обращается к серверу по HTTPS.
  UI подключается к ней через локальный named pipe, доступный указанному Windows SID.
- `Setup/*.ps1` — явная настройка LAN, установка/удаление службы и отключение LAN.

.NET включён в сборки win-x64. Отдельный SDK не требуется. Программы и скрипты пока
не подписаны. Не отключайте Defender/SmartScreen и не меняйте ExecutionPolicy для
обхода блокировки; сохраните сообщение для разбора.

## Что пока отсутствует

Kiosk/Assigned Access, защита от запуска
произвольных программ в свободном состоянии, удаление игровых
и браузерных профилей, полноценный установщик/обновление/подпись, смены и касса,
управление сотрудниками в новом окне (пока есть в локальном
веб-интерфейсе). Нет гарантии предупреждения, если окно Visitor закрыто.

**Выход из Windows закрывает процессы, но не удаляет сохранённые токены Steam,
браузера и других аккаунтов. Свободное место после выхода не защищено kiosk-политикой.**
Не допускать посетителей к этому комплекту до завершения этих работ и испытаний.
Во время паузы служба завершает Windows-сеанс выделенного посетителя и запрещает
ему оставаться вошедшим до возобновления. Несохранённые данные приложений могут пропасть.

## ПК администратора

1. Остановить предыдущий сервер, сделать проверенную копию базы. Распаковать комплект
   в отдельную папку. Для переноса данных скопировать старую `.data` в `Server/.data`
   **при остановленных обоих серверах**. Никогда не копировать живую SQLite как обычный файл.
2. Запустить `Admin/Club.Admin.exe`. На пустой базе — «Создать владельца», затем «Войти».
   Логин/пароль выбирает владелец, стандартного пароля нет.
3. Создать место и пакет. Цена тарифа, пополнение и возврат в нативном Admin вводятся **в сомах**: 100,50 = 100 сомов 50 тыйынов.
4. Закрепить IPv4 адрес ПК администратора, например `192.168.1.10`. Проверить, что это
   адрес данного ПК, сетевой профиль — Private, доступ нужен только из сети клуба.
5. Из PowerShell с правами администратора, в папке комплекта:

   ```powershell
   .\Setup\Enable-Lan.ps1 -ServerAddress 192.168.1.10
   ```

   Скрипт создаёт TLS-сертификат для указанного IP на шесть месяцев, защищает `.data`
   и файл TLS-настроек ACL, добавляет правило входящего TCP 5443 только для Private /
   LocalSubnet. Порт 5080 остаётся loopback. Сохранить показанный отпечаток сертификата.
   Перезапустить Server. Для этих настроек используется стандартное окружение Production.
6. Выбрать место, нажать «Привязать ПК», сохранить `PC.binding.json`. Файл содержит
   секрет конкретного ПК, не отправлять его в GitHub/чат и не оставлять в общей папке.
   Ключ сохраняется на сервере только как SHA-256. Привязка запрещена, если есть
   незакрытый или неподтверждённый сеанс. Повторная привязка свободного ПК меняет ключ.
   Если ответ потерян, в локальном веб-интерфейсе операции с устройствами пока нет:
   повторить отправку сохранённого JSON на `/api/admin/devices` с тем же operationId
   через авторизованный локальный API либо заново привязать свободное место новым ключом.

## Проверка комплекта игрового ПК

Установщик проверяет agent-payload.json: SHA-256, размер и полный состав файлов Agent/Visitor
до установки и после копирования. Повреждённый или неполный комплект отклоняется.
Самостоятельная проверка: `Setup\Verify-AgentPayload.ps1 -PayloadRoot .`.
Файлы привязки/сертификаты можно хранить рядом с комплектом, но не внутри Agent/Visitor.
Манифест защищает от ошибок копирования; он не является цифровой подписью издателя.
Скачивать комплект из проверенного Actions-прогона и сверять опубликованный SHA-256 архива.
Установщик сохраняет манифест в `%ProgramFiles%\Club`. Для совместимых версий Agent/Visitor
добавлено ручное обновление в режиме обслуживания с откатом. Автозагрузки обновлений,
подписи издателя и обновления Server/Admin этим скриптом нет.

## Игровой ПК

1. Подготовить отдельного **локального стандартного пользователя Windows**, например
   `ClubVisitor`, с паролем. Не использовать Windows-аккаунт сотрудника. Автовход не включается.
2. Передать комплект, файл привязки и **только публичный** `Setup/club-server.cer`.
   Сверить отпечаток по экрану ПК администратора, а не доверять файлу из неизвестного источника.
3. В PowerShell с правами администратора:

   ```powershell
   .\Setup\Install-Agent.ps1 -BindingFile .\PC.binding.json `
     -ServerUrl https://192.168.1.10:5443 -VisitorUser ClubVisitor `
     -ServerCertificate .\club-server.cer -CertificateThumbprint ОТПЕЧАТОК_С_ПК_АДМИНИСТРАТОРА
   ```

   Скрипт устанавливает файлы в `%ProgramFiles%\Club`, секрет/остаток в
   `%ProgramData%\Club\Agent` с доступом только SYSTEM и администраторам. Добавляет
   доверие ровно проверенному сертификату, создаёт службу и настраивает её перезапуск.
   Создаёт задание `\ClubVisitor`: вход только указанного SID, InteractiveToken,
   ограниченные права, без пароля в задании и без автоматического входа в Windows.
   Существующее одноимённое задание не перезаписывается. Ошибка установки требует
   разбора и отката через Uninstall-Agent; повторно поверх сохранённых данных не ставить.
   Установщик требует отсутствия `%ProgramFiles%\Club` и `%ProgramData%\Club`:
   прежнюю установку сначала удалить и явно архивировать обе папки. Новые каталоги
   создаются сразу с конечными правами; проверяются владелец и ACL до записи ключа.
   Существующие каталоги, включая заранее созданные другим пользователем, не принимаются.
   Входящих сетевых портов на игровом ПК не открывает. Удалить транспортную копию привязки.
4. Войти в Windows как `ClubVisitor`; Visitor должен открыться автоматически.
   Если он не открылся, сохранить ошибку Планировщика заданий. Ручной запуск:
   `C:\Program Files\Club\Visitor\Club.Visitor.exe`. Зарегистрироваться в клубе.
   На ПК администратора выбрать посетителя, пополнить учебный баланс. На игровом ПК
   купить пакет. Выбор другого места не предлагается: служба подставляет свою привязку.
5. Сверить номер команды и подтверждения в таблице сеансов. Пока они отличаются,
   команда ещё не подтверждена службой. Время на сервере — последнее подтверждённое;
   во время разрыва связи оно может отставать от локального таймера.

## Тарифы в приложении администратора

«Новый тариф» открывает форму с названием, длительностью и ценой в сомах (до двух
знаков после запятой). Для изменения выбрать строку на вкладке «Пакеты» и нажать
«Изменить тариф». Снятие флажка «Доступен для новых покупок» скрывает тариф от посетителей.
Повторное включение снова разрешает покупки. Условия уже купленных сеансов сохраняются.
Изменение проходит через журнал незавершённых запросов и безопасный повтор.

## Пополнение и возврат в приложении администратора

Для пополнения выбрать посетителя и нажать «Пополнить». Форма показывает его логин,
текущий баланс и предел суммы; состояние обновляется перед открытием. Ввести сумму
в сомах, например `100,50` или `100.50`, выбрать «Наличные»/«Перевод» и подтвердить
после получения оплаты. Максимум одной операции — 1 000 000 сомов; форма также
учитывает предел баланса 10 000 000 сомов.

Для возврата выбрать завершённый сеанс. На управляемом ПК нужно дождаться подтверждения
завершения. Форма показывает посетителя, место, пакет и доступную сумму, требует способ
выдачи и причину. Возврат выдаётся вручную и **не зачисляется на баланс**. Доступный предел
перепроверяется сервером при отправке; данные формы не гарантируют, что другой сотрудник
не выполнил операцию за время ввода.

Обе формы принимают не более двух десятичных знаков, без разделителей тысяч, знака
минус и экспоненты. Например `1,000` отклоняется: для тысячи сомов ввести `1000`.
Лишние знаки не округляются. Отмена не создаёт денежную операцию. В базе/API суммы
остаются целыми тыйынами; существующий механизм повторов не допускает двойного
списания/пополнения с одним номером операции. Суммы в таблицах показаны с двумя знаками
и сортируются как числа. В технических описаниях журнала могут оставаться тыйыны.

## Сотрудники

Войти владельцем: появится кнопка «Новый сотрудник». Задать отдельный логин и начальный
пароль с повтором. Форма создаёт роль администратора; передать пароль сотруднику лично.
Логин — 3–32 латинских символа, цифры, точка/дефис/подчёркивание; пароль — 10–128 символов.
Пробелы в пароле сохраняются, включая начало/конец; вход также их не удаляет.

Вкладка «Сотрудники (владелец)» показывает только логин и роль, без паролей/хэшей.
Обычный администратор не может создавать сотрудников или получать этот список:
ограничение проверяется сервером. При потере ответа обновить список перед повтором.
Повтор с тем же занятым логином не создаст второй аккаунт. Пароль не записывается
в файл незавершённых денежных запросов. Свой пароль можно изменить кнопкой «Сменить пароль», указав текущий и повторив новый.
После смены нужно войти заново на всех устройствах. Пароли не сохраняются в pending-файл.
При обновлении на эту версию старые входы также потребуют повторной авторизации.
Владелец выбирает сотрудника на вкладке «Сотрудники» и использует «Доступ сотрудника»
или «Сброс пароля сотрудника». Причина обязательна. Владельца заблокировать нельзя.
Разблокировка не восстанавливает прежние входы; сброс пароля не снимает блокировку.
Это управление сотрудниками, не завершение оплаченных игровых сеансов.

Схема базы обновляется до v3 автоматически. До обновления сохранить копию v2.
Старый Server не читает v3; восстанавливать старую версию можно только со сверкой
денег и подходящей копией. Копии v1/v2 читаются новым Server.

## Резервная копия из Admin

Нажать «Резервная копия» и выбрать **новое** имя `.db` на локальном диске или флешке.
Admin скачивает серверную online-копию во временный файл в выбранной папке, затем
запускает проверку из папки Server того же комплекта. Проверяются SQLite, структура,
связи и соответствие балансов журналу. Только после успешной проверки появляется
конечный `.db`. Существующий файл не перезаписывается даже при совпадении имени.
Отмена выбора файла не начинает выгрузку. Предел загрузки — 1 ГиБ.

Дождаться сообщения об успешном сохранении, затем безопасно извлечь носитель средствами
Windows. Прерванная/повреждённая копия не принимается как завершённая; при обрабатываемой
ошибке программа удаляет временный файл, если носитель доступен. После отключения
носителя, аварийного закрытия или сбоя питания может остаться
`.club-backup-*.part`: это не подтверждённая копия. Серверная локальная копия при сбое
скачивания может сохраниться в его папке backups.

Копия содержит аккаунты, хэши паролей и финансы, не зашифрована. Хранить носитель у владельца.
Это копия базы, не образ компьютера: TLS-сертификат/ключ и настройки Windows/агентов
нужно хранить отдельно. Отметка в журнале сервера подтверждает создание серверной копии,
но сама по себе не доказывает сохранение или извлечение флешки.

Восстановление выполняется отдельно: завершить/сверить сеансы и денежные операции,
сохранить текущую копию, остановить Server (закрытие Admin само по себе его не останавливает).
Перейти в папку Server текущей установки:

```powershell
.\Club.Server.exe --verify-backup E:\ClubBackups\club-copy.db
.\Club.Server.exe --restore-backup E:\ClubBackups\club-copy.db
```

Если задан нестандартный каталог базы, явно добавить к команде восстановления
`--Club:DataDirectory "D:\ClubData"` с реальным путём установки. Не восстанавливать
в папку другой установки. Рабочая служба/сервер удерживает блокировку базы: восстановление
при работающем Server отклоняется. Предыдущая база сохраняется, старые cookies входа
сбрасываются; после запуска активные сеансы требуют ручного продолжения. Возврат к старой
копии требует сверки денег за период после её создания. Сначала проверить процедуру
в отдельной тестовой папке.

## Каталог игр и браузера

Установить нужные программы на игровом ПК. Создать UTF-8 JSON, например `games.json`,
с реальными путями к EXE (приведённые ниже пути — пример, не поставляемые игры):

```json
[
  {
    "id": "example-game",
    "name": "Пример игры",
    "executable": "C:\\Games\\Example\\game.exe",
    "arguments": []
  },
  {
    "id": "browser",
    "name": "Браузер",
    "executable": "C:\\Program Files\\Mozilla Firefox\\firefox.exe",
    "arguments": ["--new-window", "https://example.org"]
  }
]
```

Применить из PowerShell администратора: `Setup\Set-Games.ps1 -CatalogFile .\games.json`.
Скрипт проверяет формат и наличие EXE до замены каталога. При ошибке прежний каталог
сохраняется. Хранилище — `%ProgramData%\Club\Agent\games.json`, посетителю недоступно.
Перезапуск службы не требуется; в Visitor нажать «Список игр», выбрать строку на вкладке
«Игры и браузер» и «Запустить игру». До настройки каталог пуст.

Разрешены до 100 записей с уникальными ID, полными локальными путями к EXE и массивом
заранее заданных аргументов. UNC-пути, относительные пути, скрипты и URL вместо
EXE не принимаются. URL допускается как фиксированный аргумент браузера. Изменение
аргументов/путей посетителем через API не предусмотрено. Файлы игр и их каталоги также
нужно защищать правами Windows от подмены обычным пользователем.

Запуск через Visitor требует действующего Running-сеанса с положительным остатком;
при обрыве LAN используется автономный таймер службы. Повреждённый каталог отключает
запуск, но не таймер. Игры запускаются процессом Visitor с его правами, без повышения.
Между разрешением и стартом возможна смена состояния; выход Windows остаётся задачей
службы. Самостоятельный запуск через Проводник пока не блокируется. Учёт бесплатного
сеанса сотрудника также разрешает запуск. Уже открытые игры закрываются выходом Windows,
а не этой кнопкой. Токены игровых/браузерных аккаунтов не очищаются.

## Подготовка ограничений Windows 11 Pro

После установки службы и каталога: `Setup\Export-KioskDraft.ps1 -OutputDirectory .\kiosk-trial-01`.
Это экспорт черновика XML и отчёта readiness.json, без изменения политик Windows.
Полная инструкция — `windows-kiosk.md` в комплекте ([версия в репозитории](windows-kiosk.md)).
Проверяются версия/редакция Windows, UAC, учётная запись, служба и задание автозапуска.
Даже успешная предварительная проверка не означает готовности: права на игровые файлы,
конфликт политик, зависимости игр и запрет неоплаченного доступа требуют отдельной работы.

## Обязательный журнал испытаний

Для каждого пункта записывать версии Windows/комплекта, ожидаемое/фактическое поведение,
остаток/баланс до и после, точные ошибки, время и результат. Без этих результатов этап 0.2
не завершён. CI уже выполняет сценарий с настоящей службой и тестовым HTTPS-стендом.
Следующая матрица всё равно выполняется на игровом ПК с Windows 11 и настоящим сервером.

| Сценарий | Ожидается |
|---|---|
| Автозапуск | После входа ClubVisitor одно окно, обычные права; при входе сотрудника не запускается |
| Каталог / запуск | Только заданные программы; до сеанса, при паузе/нуле/Recovery — отказ; во время оплаченного автономного сеанса — запуск |
| Повреждённый каталог | Ошибка запуска; таймер и завершение сеанса продолжают работать |
| Повтор покупки после потери ответа | Прежний operationId; одно списание |
| Чужой ключ / другая привязка / недоверенный TLS | Отказ, без покупки и без отключения проверки TLS |
| Пауза / продолжение | Выход только ClubVisitor; таймер сохранён; продолжение после подтверждения ПК |
| Предупреждение / окончание | За 5 мин видимое сообщение; по нулю выход ClubVisitor, закрытие тестовых игры и браузера |
| Закрытие Visitor | Служба и таймер продолжаются, окончание с выходом; отсутствие предупреждения фиксируется как ограничение |
| Обрыв только интернета | Не влияет на LAN и оплаченный сеанс |
| Обрыв LAN | Остаток идёт локально, новые операции не проходят; окончание работает без сервера |
| Завершение сотрудником при обрыве | Команда ожидает; возврат и повторное занятие места/аккаунта запрещены |
| Возврат LAN после окончания | Реальный остаток сверяется; никаких повторных денег/времени |
| Перезапуск сервера | На возвращении связи пауза, минимум серверного/локального остатка |
| Перезапуск службы / питание ПК | Сохранённый остаток, Recovery/Paused, продолжение только сотрудником |
| Сбой/заполнение диска | Не подтверждать команду без записи; выход посетителя/остановка службы, восстановление по журналу |
| Параллельный Windows-сеанс сотрудника | Никогда не завершается: проверяется SID |
| Повторный вход после истечения | Проверить известный пробел свободного состояния; эксплуатация запрещена до kiosk |
| Резервная копия v1 / v2 | Восстановление в отдельной папке; миграция; те же балансы; активные сеансы приостановлены |
| Удаление службы / отключение LAN | Удаляются только созданные компоненты, данные сохранены |

Остаток сохраняется примерно каждые 250 мс через flush и замену файла. Это не гарантия
нулевой потери при сбое накопителя. Сон/гибернация и физическое выключение требуют
отдельного измерения; sleep не равен перезапуску процесса.

При ошибке службы открыть журнал Windows «Приложение», источник `Club.Agent`;
для ошибок запуска также смотреть «Система» → `Service Control Manager`.

## Откат

Сначала завершить сеансы, дождаться подтверждений и сохранить базу/журнал. На игровом ПК:

```powershell
.\Setup\Uninstall-Agent.ps1
```

Удаляются только служба, созданное задание автозапуска и доверие сертификату,
добавленное этим установщиком. Изменённое чужим процессом задание скрипт не удаляет:
оно требует ручного разбора. Конфигурация, каталог,
остаток и файлы остаются для разбора; повторная установка откажет, пока администратор явно
не архивирует прежние данные. Shell/автовход/GPO не менялись.
Перед повторной установкой явно архивировать также сохранённую папку `%ProgramFiles%\Club`.
На ПК администратора: `Setup/Disable-Lan.ps1`, затем перезапустить Server.
Старый прототип 0.1 не понимает схему v2: для отката программы потребуется сохранённая
копия v1 с обязательным учётом операций, сделанных после неё. Не подменять базу без сверки денег.

## Обновление игрового ПК в режиме обслуживания

Выполнять на обновляемом игровом ПК из отдельной учётной записи администратора Windows,
вне времени обслуживания посетителя. Скрипт изменяет только тот ПК, на котором запущен.
Новый комплект должен быть получен из проверенного GitHub Actions и сверён по SHA-256 архива.
Поддерживаются только совместимые форматы agent.json, games.json и session.json;
скрипт не мигрирует их, не меняет серверную базу, сертификаты или привязку ПК.

1. В Admin приостановить или завершить сеанс, дождаться подтверждения агента.
   Выполнить выход посетителя из Windows. Отключить именно выделенную учётную запись:
   `Disable-LocalUser -Name ClubVisitor` (подставить фактическое имя).
   Отключение аккаунта само по себе **не завершает уже открытый сеанс**.
2. Из нового комплекта выполнить в Windows PowerShell от администратора:

   ```powershell
   .\Setup\Update-Agent.ps1 -PayloadRoot (Get-Location).Path
   ```

   Обновление и восстановление сериализованы эксклюзивной блокировкой обслуживания.
   Проверяется отключённый аккаунт и отсутствие загруженного профиля, идентичность службы,
   целостность установленного и нового комплектов. Running и повреждённый checkpoint запрещены.
   После остановки службы состояние проверяется ещё раз. Конфигурация, каталог и остаток
   остаются в ProgramData. Копии файлов находятся в защищённом от записи посетителем
   `%ProgramFiles%\Club\.update-<id>`. Требуется свободное место для нового и прежнего комплектов.
3. Служба запускается, скрипт ждёт новую запись checkpoint. При ошибке запуска выполняется
   возврат прежних файлов. Копия предыдущего комплекта остаётся в выведенном каталоге `previous`.
   Для ручного отката совместимой версии можно снова вызвать Update-Agent.ps1, указав
   этот `previous` как PayloadRoot, с теми же условиями режима обслуживания.
4. Проверить ClubAgent, связь с сервером и остаток в Admin. Только после проверки включить
   `Enable-LocalUser -Name ClubVisitor`. Оплаченный остаток возобновляет сотрудник явно.
   Скрипт сам не включает посетителя и не удаляет архивы. Удалять старые `.update-*` можно
   после подтверждённого испытания, когда нет `update-in-progress.json`.

Старые установки без `%ProgramFiles%\Club\agent-payload.json` автоматически не принимаются.
Если сохранился **точный исходный комплект установленной версии**, его манифест можно проверить
через Verify-AgentPayload.ps1 с `-PayloadRoot "$env:ProgramFiles\Club"` и `-ManifestPath`
к этому исходному манифесту. Только после успешной проверки скопировать его в установленный
Club. Манифест новой версии для этого не подходит. Без исходного проверяемого комплекта
не угадывать состав установки: использовать документированное удаление/повторную установку.

### Прерванное обновление

При отключении питания между заменами файлов служба остаётся Disabled, аккаунт посетителя —
отключённым. Не включать их вручную при наличии `%ProgramData%\Club\Agent\update-in-progress.json`.
Из проверенного комплекта выполнить:

```powershell
.\Setup\Repair-AgentUpdate.ps1
```

Скрипт собирает предыдущий комплект из реальных каталогов, проверяет манифест и восстанавливает
службу. Флаги журнала могут отстать от файловой операции, поэтому не служат единственным
источником решения. Перед заменой файлов восстановления сохраняется полный предыдущий
комплект, чтобы повторное прерывание не уничтожило источник отката. Удаление журнала происходит
только после запуска службы и новой записи checkpoint. При ошибке служба остаётся Disabled;
сохранить все каталоги и журнал для диагностики, посетителя не включать.

Проверка CI имитирует прерывание между перемещением и записью флага. Это не доказательство
устойчивости диска к реальному обрыву питания: испытание Windows 11 Pro и UPS остаётся обязательным.

## Посетитель забыл пароль

В Admin войти сотрудником или владельцем, выбрать человека на вкладке «Посетители» и
нажать «Сброс пароля посетителя». Перед сбросом сотрудник проверяет, что обращается владелец
аккаунта: программа не подтверждает личность по одному знанию логина. Указать новый пароль
(10–128 символов), повтор и причину восстановления без самого пароля. Поля пароля скрыты,
пробелы в пароле сохраняются. При отмене запрос не отправляется.

Сброс отзывает все прежние входы посетителя и записывает сотрудника, аккаунт и причину
в журнал. Баланс, покупки и текущий оплаченный сеанс остаются прежними; сброс не заменяет
команду паузы/завершения. Через эту команду нельзя сбросить пароль сотрудника или владельца.
Пароль не сохраняется в файле повторяемых финансовых операций. Если ответ потерян,
проверить вход новым паролем; автоматического повтора со скрыто сохранённым паролем нет.
Для владельца используется отдельная локальная процедура ниже.

## Потерян пароль владельца

Восстановление возможно только локально на ПК сервера с доступом к защищённой папке
данных; на Windows открыть консоль **от имени администратора**. Через сеть и страницу
входа эта команда недоступна. Имеющий полный доступ к серверным файлам администратор
Windows технически может менять локальную базу и вне программы — права Windows
остаются границей доверия, данная команда не доказывает личность человека.

1. Приостановить обслуживание и остановить Server. Работающая копия держит instance.lock;
   восстановление ей откажет. Не удалять файл блокировки для обхода проверки.
2. Запустить установленный Server с явным **фактическим** каталогом данных:

   ```powershell
   .\Server\Club.Server.exe --recover-owner --Club:DataDirectory 'C:\Club\Server\.data'
   ```

   Путь приведён как пример, подставить свою существующую папку. Команда не создаёт
   новую базу и не создаёт нового владельца. Нужна схема v3; миграция выполняется
   штатным запуском совместимого Server, не процедурой восстановления пароля.
3. Ввести логин существующего владельца, новый пароль 10–128 символов, повтор и причину
   без пароля. Пароль вводится скрыто; не передавать его в командной строке или файле
   общего доступа. До изменения будет сохранена проверенная копия в `backups`.
   При невозможности сохранить/проверить копию пароль не меняется.
4. Запустить Server обычной командой, войти новым паролем, проверить деньги и сеансы.
   Старые входы отозваны, блокировка владельца снята. Перезапуск сервера переводит
   незавершённые сеансы в паузу; сотрудник возобновляет их явно после сверки.

Копия `before-owner-recovery-*.db` содержит прежние хэши и состояние базы. Её восстановление
вернёт прежние учётные данные и может потерять более новые платежи: это не способ отмены
одного пароля во время работы. Хранить копию защищённо по общим правилам резервирования.

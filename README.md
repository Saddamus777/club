# Клуб — Windows/LAN pilot 0.2

ПО компьютерного клуба примерно на 30 ПК с Windows 11 Pro. Интерфейсы на русском,
расчёты в кыргызских сомах (KGS), SQLite только на ПК администратора.

**Сейчас это промежуточная реализация для испытания одного игрового ПК.
Не готова к эксплуатации и реальным деньгам. Windows-поведение службы, закрытие игр,
потеря LAN/питания и защита от обходов ещё требуют проверки на оборудовании.**

## Приложения

| Компонент | Назначение |
|---|---|
| `Club.Admin.exe` | Отдельное нативное окно сотрудника: места, пакеты, пополнение, сеансы, возвраты, сотрудники, проверенная выгрузка копии, привязка ПК, отчёт |
| `Club.Visitor.exe` | Отдельное нативное окно посетителя: регистрация, вход, баланс, покупка на своём ПК, таймер, каталог и запуск игр |
| `Club.Agent.exe` | Windows-служба игрового ПК: HTTPS, автономный таймер, сохранение остатка, выход указанного Windows-пользователя |
| `Club.Server.exe` | ASP.NET Core 10, SQLite, аккаунты/деньги/сеансы и подтверждения команд |

Windows-приложения используют WinForms, не требуют браузера или VS Code.
В обоих окнах и веб-интерфейсе есть кнопка «Чёрный фон / Светлый фон»; по умолчанию
фон чёрный. Выбор сохраняется для следующего запуска отдельно в каждом приложении
и в браузере. Таблицы и формы ввода Windows также меняют цвета.
Служба работает независимо от окна посетителя. Веб-интерфейс предыдущего прототипа
сохранён для локального доступа на ПК администратора.

Установка добавляет запуск Visitor при входе выделенного Windows-пользователя через
задание с ограниченными правами. Каталог игр и браузера задаёт сотрудник через
`Setup/Set-Games.ps1`; посетитель выбирает название, а служба проверяет действующий
сеанс перед разрешением запуска. Игра запускается самим Visitor с правами посетителя.
Уже оплаченный сеанс допускает запуск при потере LAN. Каталог не заменяет kiosk-защиту.
`Setup/Export-KioskDraft.ps1` готовит черновик Assigned Access и отчёт проверки
установленного игрового ПК. Политики Windows не применяются;
[инструкция для Windows 11 Pro](docs/windows-kiosk.md) описывает ограничения и испытания.

LAN включается явно: конкретный IP, HTTPS, сертификат с проверкой доверия и имени,
отдельный секрет каждого ПК. Ключ недоступен стандартному Windows-посетителю;
служба предоставляет ему ограниченный локальный API через named pipe.
Без настройки LAN сервер слушает только `127.0.0.1:5080`.

При обрыве LAN служба доигрывает сохранённый остаток по монотонному таймеру.
Сервер ждёт подтверждения паузы/завершения; до него нельзя повторно занять место или
выдать возврат. Перезапуск службы/сервера требует ручного возобновления, расход
автономного времени сверяется по меньшему остатку. Это проверено модельными тестами;
физические сбои и Windows-системные вызовы требуют отдельных испытаний.

На Windows Server 2025 также
проверены установка/удаление настоящей службы, права обычных пользователей, каталог,
автономный таймер, Recovery после перезапуска и истечение времени без сервера.
Тест использует управляемый HTTPS-стенд на одном ПК; Windows 11, два физических ПК,
выход интерактивного посетителя и закрытие реальных игр пока не подтверждены.

Комплект `club-pilot-0.2-win-x64` собирает workflow **Validate club pilot** в GitHub
Actions, если Windows job завершился успешно. Внутри отдельные папки Admin, Server,
Visitor, Agent и Setup. Runtime включён. Статус Actions надо проверять для нужного
коммита; наличие workflow само по себе не доказывает успешную проверку.

Архив в `downloads/club-prototype-0.1-win-x64.zip` — **предыдущий веб-прототип 0.1.1**,
без новых приложений и LAN. Он сохранён для истории, не является комплектом 0.2.

В нативном приложении цена тарифа, пополнение и возврат вводятся в сомах.
Для пополнения/возврата допустимы `100,50` и `100.50`; лишние десятичные знаки
отклоняются без округления. Способ оплаты выбирается как «Наличные» или «Перевод».
Балансы и доступные возвраты также показаны в сомах. Для начала создать владельца,
место и тариф, настроить LAN, привязать устройство, установить службу под отдельного
стандартного Windows-пользователя, затем зарегистрировать посетителя и пополнить его
учебный баланс. Полные команды и откат — в инструкции, не устанавливать сразу на 30 ПК.

Владелец блокирует/разблокирует сотрудников и сбрасывает их пароли с указанием причины.
Старые входы отзываются и не восстанавливаются при разблокировке.
Владелец создаёт сотрудников кнопкой «Новый сотрудник» и видит их список. Пароли
не сохраняются в журнал повторов. Кнопка «Резервная копия» выгружает SQLite прямо из
Admin: сначала временный файл, затем проверка целостности/финансового журнала и сохранение
под новым именем. Существующие копии не перезаписываются. Для проверки нужна папка Server
из того же комплекта; восстановление выполняется отдельно при остановленном сервере.

## Сохранённая логика учёта

- Персональные аккаунты, роли на сервере, PBKDF2, HttpOnly cookies, CSRF и ограничение входа.
- Балансы в целых тыйынах; транзакции, идентификаторы операций и безопасный повтор.
- Один незавершённый/неподтверждённый сеанс на место и посетителя; пауза, продолжение,
  завершение, бесплатное время с причиной.
- Ручная компенсация неиспользованного времени без автоматического зачисления на баланс.
- Журнал и отчёт, online backup раз в шесть часов, проверка и восстановление копии.
- Миграция схемы v1/v2 → v3. Новая версия читает старые копии; прежний Server не читает v3.

При обновлении сохранять `.data`; не заменять живую базу файлом из другой установки.
Секреты устройств, TLS-ключи и базы нельзя помещать в GitHub. Копии содержат личные
данные/финансы, шифрование резервных копий пока отсутствует.

## Что остаётся

Kiosk/Assigned Access и защита свободного рабочего места,
очистка сохранённых входов Steam/браузеров, подписанный установщик и обновления,
полный набор административных функций в нативном окне, смены/касса, сложные акции,
восстановление паролей и отзыв доступа, испытания диска/питания/30 ПК.
Один выход из Windows не очищает чужие аккаунты и не закрывает все пути обхода.

## Разработка и проверки

```bash
cd /workspace/club
bash scripts/setup-cloud.sh
bash scripts/dotnet.sh test tests/Club.Tests -c Release --no-restore
CLUB_PACKAGED_CHROMIUM=1 node tests/browser/smoke.cjs
python3 tests/tls-smoke.py
bash scripts/publish-pilot.sh
```

SDK 10.0.402 закреплён в `global.json`; загрузка проверяется SHA-512, NuGet/npm зависимости
закреплены lockfile. `setup-cloud.sh` восстанавливает и собирает все проекты, включая
кросс-компиляцию Windows. Без облачной обёртки — обычные `dotnet restore Club.slnx
--locked-mode`, `dotnet build Club.slnx -c Release --no-restore`, `dotnet test tests/Club.Tests`.

`publish-pilot.sh` создаёт новый staging-каталог, self-contained Windows x64 архив
в `artifacts/club-pilot-0.2-win-x64.zip` и SHA-256; базы/секреты в комплект не входят.
Кросс-сборка на Linux не подтверждает работу Windows. Workflow проверяет серверные тесты
на Linux/Windows, запускает оба нативных окна в smoke-режиме и выполняет установку,
испытание и удаление службы на чистом Windows runner. Реальные интерактивные
пользовательские сеансы и игры в CI не завершаются. Полный результат — в docs/validation.md.

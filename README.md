# Клуб — прототип 0.1

Первый проверяемый шаг системы для компьютерного клуба примерно на 30 ПК с Windows 11.
Интерфейс на русском, расчёты в кыргызских сомах (KGS). Сервер: C# / ASP.NET Core 10;
база: SQLite. Браузерный интерфейс без сторонних JS-зависимостей.

**Это учебный локальный прототип учёта. Он не блокирует Windows, не завершает игры,
не разрешает безопасную работу 30 игровых ПК и не готов принимать реальные деньги.**
Только loopback, без доступа из локальной сети. Не открывайте порт через прокси или туннель.

## Что реализовано

- Создание владельца локальной командой без стандартного пароля; персональные аккаунты
  администраторов и самостоятельная регистрация посетителей.
- Вход, роли и проверка полномочий на сервере. Пароли хэшируются PBKDF2; cookies HttpOnly,
  SameSite Strict, защита POST от CSRF, ограничение частоты входа/регистрации.
- Тестовые места, создание/изменение/скрытие пакетов; простой акционный пакет с отдельной ценой.
- Ручные пополнения наличными/переводом, покупка пакета посетителем, баланс в целых тыйынах.
- Транзакции и идемпотентность: повтор одинакового запроса не повторяет денежную операцию.
  Неизвестный результат в браузере сохраняется до повторной проверки.
- Один незавершённый сеанс на посетителя и место; время, пауза/возобновление/завершение
  сотрудником, бесплатное время с обязательной причиной, предупреждение посетителю за 5 минут.
- При перезапуске сервера активные сеансы становятся приостановленными с последним
  сохранённым остатком. Простой не расходуется. Для прототипа разрыв серверного таймера
  более 15 секунд либо перевод часов назад также требуют ручного возобновления.
- Ручной возврат за неиспользованную часть закрытого сеанса; он учитывается отдельно
  и не возвращает деньги на внутренний баланс. Повторное использование времени запрещено.
- Отчёт за всё время: пополнения, покупки, возвраты, балансы, наличные/переводы,
  операции по сотрудникам; последние 100 событий журнала. Данные журнала не обрезаются.
- SQLite Online Backup: локальные копии при работе сервера раз в 6 часов и скачивание
  проверенной копии для флешки; команды проверки и восстановления с сохранением предыдущей базы.

## Что ещё предстоит

Windows-служба и клиент, реальная блокировка/выход из сеанса, работа при потере LAN,
безопасная привязка клиента к конкретному ПК, очистка личных аккаунтов, установка и обновление,
TLS и авторизация устройств, полноценные акции, смены/сверка кассы и загрузка за период,
смена/восстановление паролей, отзыв доступа сотрудников, диагностика аппаратных сбоев.
Подробнее: [согласованные правила и этапы](docs/specification.md).

## Запуск на Windows 11 x64 без VS Code

**[Скачать готовый комплект Windows из GitHub](https://github.com/Saddamus777/club/blob/main/downloads/club-prototype-0.1-win-x64.zip?raw=true)**

Если GitHub предлагает открыть страницу файла, нажмите **Download raw file**.
Для закрытого репозитория сначала войдите в GitHub под аккаунтом с доступом.
Не путайте готовый комплект с **Code → Download ZIP**: эта команда скачивает весь
репозиторий с исходниками. Готовый комплект расположен отдельно в папке `downloads/`.

Для проверки нужен комплект `artifacts/club-prototype-0.1-win-x64.zip`.
Он содержит .NET runtime; отдельный SDK не нужен. Windows-сборка не подписана.
Не меняйте настройки защиты Windows ради запуска — при блокировке сообщите текст ошибки.
Полная инструкция: [первое испытание на Windows](docs/windows-test.md).

1. Распаковать архив в отдельную доступную для записи папку, например `C:\ClubPrototype`.
2. Один раз выполнить `01-create-owner.cmd` и выбрать логин/пароль.
3. Выполнить `02-start.cmd`; после сообщения о запуске — `03-open.cmd`.
4. Проверить сценарий на учебных суммах из инструкции. Остановка сервера: Ctrl+C.

База, ключи cookies и локальные копии лежат в `.data` рядом с исполняемым файлом.
Не заменяйте и не удаляйте эту папку при обновлении. Копии содержат аккаунты,
хэши паролей и финансы; храните флешки у владельца. Шифрование копий в этой версии не реализовано.

## Разработка в облачной среде

```bash
cd /workspace/club
bash scripts/setup-cloud.sh
bash scripts/dotnet.sh test Club.slnx -c Release --no-restore
bash scripts/run-cloud.sh --create-owner
bash scripts/run-cloud.sh
```

SDK 10.0.402 загружается с сервера Microsoft с проверкой SHA-512 из официальных метаданных.
Зависимости закреплены в `packages.lock.json`, восстановление в настройке среды — locked mode.
Если sandbox запрещает создание именованных mutex .NET в `/home/agent/.dotnet`,
используйте штатное разрешение расширенного запуска команды; не меняйте HOME и не отключайте проверки.
Требуемые сетевые назначения: `builds.dotnet.microsoft.com`, `api.nuget.org` и NuGet CDN.

`scripts/run-cloud.sh` хранит данные разработки в `/workspace/club/.data/development`.
Команды установки и запуска не создают пользователя с заранее заданным паролем.
Проверка доступности: локальный HTTP GET `/health` должен вернуть `status: ok`.
Функциональная готовность проверяется тестами, а не только health endpoint.

Проверка браузера в Linux (сначала остановить свой сервер, порт 5080 должен быть свободен):

```bash
CLUB_PACKAGED_CHROMIUM=1 node tests/browser/smoke.cjs
```

Настройка среды устанавливает закреплённые тестовые npm-зависимости. Chromium для этой
проверки поставляется в пакете `@sparticuz/chromium`, без отдельной загрузки с CDN.
Проверка создаёт временную базу и случайные пароли, запускает и останавливает только свой сервер.
Снимки интерфейса сохраняются в `artifacts/`. При неизвестном исходе финансового запроса
проверяется повтор с тем же идентификатором, без повторного пополнения.

В любой другой среде с .NET SDK из `global.json`:

```bash
dotnet restore Club.slnx --locked-mode
dotnet test Club.slnx -c Release --no-restore
dotnet run --project src/Club.Server -- --create-owner
dotnet run --project src/Club.Server
```

Для собственной папки данных задайте `Club__DataDirectory` перед обоими запусками.
По умолчанию `.data` располагается рядом с собранным приложением, поэтому не переключайте
конфигурацию Debug/Release с реальными данными без явного указания папки.

## Сборка комплекта Windows из облачной среды

```bash
bash scripts/publish-windows.sh
```

Архив, его SHA-256 и распакованный комплект находятся в `artifacts/` и не входят в Git.
Кросс-сборка на Linux не подтверждает запуск исполняемого файла на Windows.
Текущие результаты проверок: [validation.md](docs/validation.md).

Первый готовый комплект также сохранён в `downloads/`, чтобы его можно было скачать
с GitHub без SDK и сборки. Проверка SHA-256 находится рядом с ZIP. Скрипт сборки
создаёт новые результаты в `artifacts/`; опубликованный файл в `downloads/` нужно
обновлять явно после проверки соответствующей версии.
